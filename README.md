# BorgBackup — Home Assistant Integration

[![HACS Badge](https://img.shields.io/badge/HACS-Custom-orange.svg)](https://github.com/hacs/integration)
[![License](https://img.shields.io/github/license/maltejk/homeassistant-borgbackup-integration)](LICENSE)

A Home Assistant custom integration that registers a **BorgBackup backup agent**, bridging
Home Assistant's native backup UI to the [BorgBackup Add-on](https://github.com/maltejk/homeassistant-borgbackup-app)
via a local HTTP API.

This is AI generated code. Please find the instructions in [copilot-instructions.md](.github/copilot-instructions.md).

---

## How it works

```
Home Assistant Backup UI
        │
        ▼
 BorgBackupAgent  (this integration)
        │  HTTP REST on port 8774
        ▼
 BorgBackup Add-on ──► Borg repository
   (Docker container)    (local or remote SSH)
```

The integration is a **thin HTTP client** — it sends backup data to the add-on and receives it back. All Borg-specific configuration (repository path, passphrase, SSH key, pruning policy) lives in the add-on, not in the integration.

### Via HACS (recommended)


### Manual

Copy `custom_components/borgbackup/` into `config/custom_components/` and restart

## Setup

### Automatic (Supervisor discovery)

If the BorgBackup add-on is installed as a Home Assistant add-on, it publishes its
connection details via Supervisor. Home Assistant will prompt you to confirm the
detected settings — no manual entry needed.

### Manual

Go to **Settings → Devices & Services → Add Integration**, search for **BorgBackup**,
and enter:

| Field    | Default            | Description                                           |
|----------|--------------------|-------------------------------------------------------|
| Host     | `local-borgbackup` | Hostname or IP where the add-on is reachable          |
| Port     | `8774`             | API port (must match add-on setting)                  |
| API Key  | —                  | Auto-generated by the add-on; shown in the add-on log on first start |

To find the API key, check the add-on log immediately after it starts for a line like:
```
INFO  Generated API key: <key>
```

## Reconfigure / Re-authentication

- **Reconfigure**: change host, port, or API key at any time via the integration's
  three-dot menu → **Reconfigure**.
- **Re-authentication**: if the API key changes (e.g. after a data volume reset),
  Home Assistant will prompt for a new key automatically.

## Supported operations

| Operation       | Description                                          |
|-----------------|------------------------------------------------------|
| List backups    | Shows all HA backups archived in the Borg repository |
| Upload backup   | Streams a new backup through the add-on into Borg    |
| Download backup | Streams a backup back for restore                    |
| Delete backup   | Removes a backup archive from Borg                   |

Pruning (keep-daily / keep-weekly / keep-monthly) is configured in the add-on and
runs automatically after each upload.

---

## How backups are stored

Each backup is a Borg archive named `ha-<backup-id>`. The full HA metadata dict is
stored as JSON in the archive comment — no sidecar files, no extra storage overhead.

## Troubleshooting

**"Cannot connect"** — Check that the add-on is running and that Home Assistant can
reach the configured host and port. For add-ons on the same HA host, the default
hostname `local-borgbackup` only works when the add-on is installed through the HA
Supervisor. For external Docker hosts, use the actual IP or hostname.

**"Invalid API key"** — The API key was changed or the add-on data volume was reset.
Use **Reconfigure** to enter the new key, or check the add-on log for the generated
key.

**Backups not appearing** — The backup list is cached for up to 5 minutes. Wait a
moment or check the HA log for errors.

**Debug logging** — Add to `configuration.yaml`:

```yaml
logger:
  default: info
  logs:
    custom_components.borgbackup: debug
```

## Configuration

If the BorgBackup add-on is running, Home Assistant will detect it automatically via
Supervisor discovery. For a manually hosted add-on, use the **Add Integration** flow and
provide:

| Field    | Default             | Description                            |
|----------|---------------------|----------------------------------------|
| Host     | `local-borgbackup`  | Hostname / IP of the add-on            |
| Port     | `8774`              | API port (default matches add-on)      |
| API Key  | —                   | Generated by the add-on on first start |

The API key is shown in the add-on log on first start.
